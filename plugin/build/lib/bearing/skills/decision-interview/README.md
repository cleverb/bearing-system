# decision-interview

The live counterpart to `decision-recovery`. Where Recovery mines historical evidence in batch, Interview elicits testimony from a human at the moment an agent hits real ambiguity — structured, EOCR-tagged, and pressure-tested before it becomes a candidate.

## No second shadow graph

This Skill produces exactly the same candidate object Recovery does: same schema, same five evidence axes, same lifecycle states, same promotion boundary, same cost ledger. The only field that differs is `evidence_source`, which takes the value `live_interview`.

That is deliberate beyond tidiness. It means the two Skills can corroborate or contradict each other on the same subject inside one graph — a live answer can directly override a weak archaeological candidate, because they are the same kind of object competing on the same axes rather than two systems that need reconciling afterwards.

## Schema resolution

There is no `schemas/` directory here. The candidate and evidence schemas belong to `decision-recovery` and are resolved at runtime:

```bash
bearing schema candidate    # prints the resolved path
```

This is not the same as the earlier spec's "imports `decision-recovery`'s schema directly." A literal `../decision-recovery/schemas/candidate.schema.json` breaks the moment the plugin is installed, because clients copy the plugin and Agent Plugins v1.0.0 §4.1.3 requires them to reject package paths resolving outside the plugin root. The CLI resolves from the plugin root instead, which works whether BEARING is installed, vendored, or run from a checkout.

## Where this Skill's data lives

- Candidates — `<decisions.path>/shadow/candidates.jsonl`, the same file Recovery writes to.
- Transcripts — `<decisions.path>/shadow/<transcripts_dir>/`, subject to `interview.transcripts.retention`. See `references/transcript-handling.md`.
- Cost — `.bearing/ledger/cost.jsonl`, under `evidence_source: live_interview`, so cost per promoted candidate stays comparable across both acquisition modes.

Interview duration is logged exactly rather than estimated. That is the one cost figure in the whole system that needs no uncertainty range, because the person experienced it in real time.

## Maintenance model

`subagents/decision-interviewer.md` is canonical; runtime adapters are generated by `bearing render` and carry no independent authority.
