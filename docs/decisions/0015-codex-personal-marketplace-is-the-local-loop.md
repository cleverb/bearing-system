# ADR-0015: Codex contributor install is a personal-marketplace copy

* **Date:** 2026-08-24
* **Deciders:** BEARING maintainers
* **Tickets:**

## Context and Problem Statement

Cursor contributor iteration copies `plugin/` to
`~/.cursor/plugins/local/bearing-plugin` (ADR-0013). Cursor auto-discovers that
folder. Codex has no equivalent `~/.codex/plugins/local` auto-load path.

What looks like a local plugin folder under `~/.codex/plugins/` is the install
**cache** (`cache/<marketplace>/<plugin>/<version>/`). Codex's documented
contributor analogue is:

* plugin source at `~/.codex/plugins/<name>` (sibling of `cache/`, not inside it)
* personal catalog at `~/.agents/plugins/marketplace.json`
* `source.path` `./.codex/plugins/<name>` relative to home
* after install, the runtime loads the cache copy and re-syncs from source on restart

Dropping a tree into `~/.codex/plugins/local/` would not be discovered. A symlink
from `plugin/` cannot carry both Cursor's local MCP adapter and Codex's
`.mcp.json` load path. Contributors need one `bearing package --local` that
projects the canonical `plugin/` tree into both dests.

## Decision Drivers

* One canonical `plugin/` tree; Cursor local and Codex personal are load-path
  adapters, not separate codebases (ADR-0003).
* The plugin tree stays read-only at runtime; maintainer projection may write
  generated manifests into `plugin/` (ADR-0002).
* Operator facts belong in home directories, not repo config (ADR-0007). The
  personal marketplace file is an operator catalog, like `~/.bearing/bin`.
* Codex local install directories are copy targets, not git checkouts.
* Do not invent a `plugins/local` convention Codex does not honor.

## Considered Options

1. Document `codex plugin marketplace add .` against this checkout and require a
   reinstall after every `plugin/` edit.
2. Invent `~/.codex/plugins/local/bearing` to mirror Cursor's folder name.
3. Copy `plugin/` to `~/.codex/plugins/bearing`, upsert
   `~/.agents/plugins/marketplace.json` with a `bearing` entry, and generate
   `plugin/.mcp.json` plus Codex `skills` / `mcpServers` pointers.

## Decision Outcome

Chosen option: **3**.

* `plugin/.mcp.json` — Codex MCP adapter (direct server map, `${PLUGIN_ROOT}`).
* `plugin/.codex-plugin/plugin.json` points at `./skills/` and `./.mcp.json`.
* `bearing package --local` copies `plugin/` to `~/.codex/plugins/bearing`
  without overlaying Cursor's `mcp.local.json`.
* The same command upserts the personal marketplace; it does not replace the
  file or other plugin entries, and it does not run `codex plugin install`.
* `--dest` remains Cursor-only. `--codex-dest` and `--codex-marketplace` exist
  so tests never write the real home cache.

## Consequences

* Tier 0 contributor iteration is `bearing package --local`, then reload Cursor
  and restart Codex. Codex still needs a one-time personal-marketplace install.
* `~/.codex/plugins/bearing` is solely a copy target — no `.git`, not a second
  checkout.
* Re-run `--local` and restart Codex after `plugin/` edits so the cache picks
  up the source tree.
* This does not qualify Codex as a supported runtime (ADR-0011).

## Deletion test

Without this loop, Codex contributor installs either point at a stale cache copy
or require a hand-maintained tree under `~/.codex/plugins/` plus a hand-edited
personal marketplace — a second codebase beside `plugin/`, the failure mode
this distribution layer exists to prevent.
